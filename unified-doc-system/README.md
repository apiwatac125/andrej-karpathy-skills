# ระบบงานเอกสาร — กลุ่มงานพยาธิวิทยาคลินิกและเทคนิคการแพทย์ โรงพยาบาลเลิดสิน

หน้าหลักที่รวมระบบงานเอกสารทั้งหมดไว้ในที่เดียว ตามแบบร่าง:

- **แถบซ้าย** — ข้อมูลผู้ใช้ (ชื่อ ระดับสิทธิ์ งาน) พร้อมปุ่ม ‹ ซ่อนแถบ แล้วตามด้วยเมนูแยกกลุ่ม
  - WI, SP, SOP › ส่งคำขอแก้ไขเอกสาร · ส่งเอกสารที่แก้พร้อมลงนาม · ติดตามสถานะ · คลังเอกสาร
  - ระบบจัดซื้อ › คัดเลือกผู้ขาย / ผู้ให้บริการ · ประเมินผู้ขาย · คลังเอกสาร · ดรอปดาวน์รายชื่อบริษัท (ระบบ SP-MT-07)
  - ช่องสำรองสำหรับระบบใหม่ 3 ช่อง
- **หัว** — โลโก้ + "ระบบงานเอกสาร กลุ่มงานพยาธิวิทยาคลินิกและเทคนิคการแพทย์ โรงพยาบาลเลิดสิน"
- **กรอบเนื้อหา** — หน้าจอของระบบที่เลือกจากเมนู
- **แชทบอท** — ปุ่มมุมขวาล่าง ค้นเอกสารในคลัง
- จอโทรศัพท์: แถบซ้ายกลายเป็นลิ้นชัก เปิดด้วยปุ่ม ☰

เขียนด้วย Google Apps Script (HtmlService + Google Sheets) แบบเดียวกับระบบส่งไฟล์ WI พร้อมลายเซ็นออนไลน์
เพื่อให้ย้ายมารวมเป็นโปรเจกต์เดียวกันได้

## ไฟล์

| ไฟล์ | หน้าที่ |
|---|---|
| `Config.gs` | ชื่อระบบ โลโก้ ระดับสิทธิ์ และเมนูแถบซ้าย (รวมช่องสำรอง) — แก้ที่นี่ที่เดียว |
| `Auth.gs` | เข้าสู่ระบบ session รหัสผ่าน และจัดการผู้ใช้ |
| `Code.gs` | `doGet` เปิดหน้าหลัก, ส่งเมนูตามสิทธิ์, ตรวจสิทธิ์ก่อนเปิดทุกเมนู |
| `Search.gs` | แชทบอทค้นเอกสารในคลัง |
| `Settings.gs` | หน้าตั้งค่าระบบของผู้ดูแลระบบ: ชื่อระบบ/โลโก้ ลิงก์เชื่อมระบบ ระดับสิทธิ์ของแต่ละเมนู |
| `Index.html` | หน้าเว็บ: เข้าสู่ระบบ แถบซ้าย หัว กรอบเนื้อหา แชทบอท จัดการผู้ใช้ เปลี่ยนรหัสผ่าน |
| `Styles.html` | CSS (สีและฟอนต์ชุดเดียวกับระบบ WI) |
| `appsscript.json` | manifest — เวลาไทย, เว็บแอปเปิดให้ทุกคนเข้าถึงได้เพราะมีระบบ login ของตัวเอง |
| `preview/` | สร้างหน้าตัวอย่างที่เปิดดูได้โดยไม่ต้อง deploy (ดูท้ายไฟล์) |

## ติดตั้ง

1. สร้างโปรเจกต์ใหม่ที่ <https://script.google.com> แล้วคัดลอกไฟล์ `.gs` และ `.html` ทั้งหมดเข้าไป
   (ชื่อไฟล์ต้องตรง: `Index`, `Styles`) และเปิด Project Settings › Show "appsscript.json" แล้ววางเนื้อหาจากไฟล์นี้
   — หรือใช้ clasp ตามหัวข้อ "Deploy ด้วย clasp" ด้านล่าง (โปรเจกต์ของกลุ่มงานสร้างไว้แล้ว)
2. เลือกฟังก์ชัน `setup` แล้วกด Run (อนุญาตสิทธิ์ครั้งแรก) — ระบบสร้างสเปรดชีต
   "ระบบงานเอกสาร — ผู้ใช้และสิทธิ์" และบัญชี `admin` ระดับผู้ดูแลระบบ
   **รหัสผ่านชั่วคราวอยู่ใน Execution log**
   - รันซ้ำได้ ถ้าบัญชี `admin` มีอยู่แล้วแต่ยังไม่มีผู้ดูแลระบบ จะปรับ `admin` เป็นผู้ดูแลระบบให้ (รหัสผ่านเดิม)
   - ถ้าอยากเก็บผู้ใช้ในสเปรดชีตที่มีอยู่แล้ว ให้ตั้ง Script Property `DB_SHEET_ID` เป็น ID ของสเปรดชีตนั้นก่อนรัน
3. Deploy › New deployment › Web app — Execute as: **Me**, Who has access: **Anyone**
4. เปิด URL ที่ได้ เข้าสู่ระบบด้วย `admin` แล้ว **เปลี่ยนรหัสผ่านทันที** จากนั้นเพิ่มผู้ใช้ที่เมนู "จัดการผู้ใช้และสิทธิ์"
5. เชื่อมระบบอื่น — ผู้ดูแลระบบแก้ได้ที่หน้า "ตั้งค่าระบบ" ในเว็บ (หรือที่ Project Settings › Script Properties)

   | Property | ค่า |
   |---|---|
   | `SPMT07_APP_URL` | URL เว็บแอป SP-MT-07 production (deploymentId อยู่ใน CLAUDE.md ของ repo `spmt07-webapp`) |
   | `SPMT07_SHEET_ID` | id สเปรดชีต "SP-MT-07 Selection Submissions" (ส่วนยาวใน URL ของชีต ระหว่าง `/d/` กับ `/edit`) — ใช้กับแชทบอท |
   | `WI_APP_URL` | URL เว็บแอประบบ WI (ลงท้าย `/exec`) |

   ค่าเหล่านี้ไม่เขียนไว้ใน repo เพราะ repo นี้เปิดสาธารณะ — URL ระบบจริงของโรงพยาบาลไม่ควรอยู่ที่สาธารณะ
   ถ้ามีไฟล์ `LocalProps.gs` (ดูหัวข้อ Deploy ด้วย clasp) `setup()` จะเติมให้เองเฉพาะตัวที่ยังว่าง

## Deploy ด้วย clasp

`.clasp.json` ในโฟลเดอร์นี้ชี้ไปที่โปรเจกต์ Apps Script "ระบบงานเอกสาร" ของกลุ่มงาน และ `.claspignore`
push ขึ้นไปเฉพาะไฟล์ของระบบ (ไม่เอา README / preview)

```bash
clasp push
clasp list-deployments          # ดู deploymentId ของตัว production
clasp deploy --deploymentId <deploymentId> --description "..."
```

`clasp push` อย่างเดียวลิงก์ production ยังใช้โค้ดเดิม ต้อง `clasp deploy --deploymentId` ทุกครั้ง

`LocalProps.gs` (อยู่ใน `.gitignore`) ใช้ส่งค่า Script Properties ขึ้นไปพร้อมโค้ดโดยไม่ต้องพิมพ์เองในหน้า Project Settings:

```js
var LOCAL_PROPS = { SPMT07_APP_URL: 'https://script.google.com/macros/s/…/exec', SPMT07_SHEET_ID: '…' };
```

push แล้วรัน `setup()` หนึ่งครั้ง ค่าจะถูกคัดลอกลง Script Properties — push ครั้งหลังที่ไม่มีไฟล์นี้ก็ไม่เป็นไร

## ระดับสิทธิ์

5 ระดับ เรียงจากสูงไปต่ำ: **ผู้ดูแลระบบ (admin)** › หัวหน้ากลุ่มงาน › หัวหน้างาน › ผู้ปฏิบัติงาน › อื่นๆ

| เมนู | ผู้ดูแลระบบ | หัวหน้ากลุ่มงาน | หัวหน้างาน | ผู้ปฏิบัติงาน | อื่นๆ |
|---|:-:|:-:|:-:|:-:|:-:|
| ส่งคำขอแก้ไขเอกสาร | ✓ | ✓ | ✓ | ✓ | – |
| ส่งเอกสารที่แก้พร้อมลงนาม | ✓ | ✓ | ✓ | ✓ | – |
| ติดตามสถานะ | ✓ | ✓ | ✓ | ✓ | – |
| คลังเอกสาร (WI) | ✓ | ✓ | ✓ | ✓ | ✓ |
| คัดเลือกผู้ขาย / ผู้ให้บริการ | ✓ | ✓ | ✓ | ✓ | – |
| ประเมินผู้ขาย | ✓ | ✓ | ✓ | ✓ | – |
| คลังเอกสาร (ระบบจัดซื้อ) | ✓ | ✓ | ✓ | ✓ | – |
| ดรอปดาวน์รายชื่อบริษัท | ✓ | ✓ | ✓ | – | – |
| จัดการผู้ใช้และตั้งค่าระบบ | ✓ | – | – | – | – |

- นี่คือค่าเริ่มต้น (`minLevel` ใน `Config.gs`) ผู้ดูแลระบบเปลี่ยนระดับของแต่ละเมนูได้ที่หน้า "ตั้งค่าระบบ"
  และหน้า "จัดการผู้ใช้และสิทธิ์" แสดงตารางนี้จากค่าที่ใช้จริงเสมอ
- **ผู้ดูแลระบบแก้ได้ทุกอย่างจากหน้าเว็บ**: เพิ่ม/แก้ผู้ใช้และกำหนดระดับ (รวมตั้งผู้ดูแลระบบคนอื่น) ตั้งรหัสผ่านใหม่
  ปิดบัญชี และหน้า "ตั้งค่าระบบ" (ชื่อระบบ หน่วยงาน โลโก้ · ลิงก์เชื่อมระบบ WI / SP-MT-07 · ระดับสิทธิ์ของแต่ละเมนู)
- ถ้าให้หัวหน้ากลุ่มงานจัดการผู้ใช้และตั้งค่าได้ด้วย เปลี่ยน `ADMIN_LEVEL` ใน `Config.gs` เป็น 4
- เพิ่มระดับใหม่ได้ที่ `ROLES` ใน `Config.gs`
- ผู้ใช้เห็นเฉพาะเมนูที่ระดับของตัวเองเปิดได้ และ server ตรวจสิทธิ์ซ้ำทุกครั้งที่เปิดเมนู
- เปลี่ยนระดับหรือปิดบัญชีแล้วมีผลทันที (session เก็บแค่ชื่อผู้ใช้ สิทธิ์อ่านจากชีตใหม่ทุกครั้ง)
- ผู้ดูแลระบบลดสิทธิ์หรือปิดบัญชีของตัวเองไม่ได้ กันระบบเหลือแต่ผู้ใช้ที่จัดการสิทธิ์ไม่ได้
- หน้าตั้งค่ารับเฉพาะลิงก์ที่ขึ้นต้นด้วย `https://` และตรวจทุกช่องก่อนบันทึก ช่องไหนผิดจะไม่บันทึกอะไรเลย

## เพิ่มระบบใหม่ในช่องสำรอง

แทนที่ `{ slot: true }` ใน `MENU` ด้วยกลุ่มเมนูจริง เช่น

```js
{
  group: 'ระบบความเสี่ยง',
  items: [
    { id: 'risk-report', label: 'รายงานความเสี่ยง', minLevel: 2, app: 'RISK_APP_URL', page: 'report' }
  ]
},
```

- `app` + `page` — ระบบที่ deploy แยก: ตั้ง Script Property ชื่อตาม `app` เป็น URL เว็บแอป ระบบจะโหลด `URL?page=report&embed=1`
- `file` — หน้าที่อยู่ในโปรเจกต์นี้เอง: สร้าง `ชื่อไฟล์.html` แล้วใส่ `file: 'ชื่อไฟล์'` หน้านั้นได้ตัวแปร `user` และ `token`
  ใน template และเปิดได้เฉพาะคนที่สิทธิ์ถึง
- ไม่ใส่ทั้งสองอย่าง = แสดง "เร็วๆ นี้" และหน้า "อยู่ระหว่างพัฒนา" ใช้จองเมนูไว้ก่อนระบบพร้อม

## เชื่อมระบบจัดซื้อ (SP-MT-07 คัดเลือกและประเมินผู้ขาย)

ระบบ SP-MT-07 (repo `Unlucky125/spmt07-webapp`) deploy แยกโปรเจกต์ใช้งานจริงอยู่แล้ว เมนูใต้ "ระบบจัดซื้อ"
เปิดหน้าของระบบนั้นในกรอบเนื้อหา:

| เมนู | หน้าใน SP-MT-07 |
|---|---|
| คัดเลือกผู้ขาย / ผู้ให้บริการ | หน้าแรก (แบบคัดเลือก FR-SPMT07-01 / -09) |
| ประเมินผู้ขาย | `?page=summary` (สรุปผลการประเมินประจำปี) |
| คลังเอกสาร | `?page=archive` |
| ดรอปดาวน์รายชื่อบริษัท | `?page=formtools` |

SP-MT-07 ตั้งแต่ version 28 (deploy 2026-10-29) รองรับ `?embed=1` แล้ว: หน้าเหล่านี้แสดงในกรอบได้
และซ่อนลิงก์ไปหน้าอื่นของ SP-MT-07 (ใช้เมนูซ้ายแทน) ลิงก์ Google Form ยังอยู่ เปิดตรงไม่มี `?embed=1`
เหมือนเดิมทุกอย่าง — ฝั่งนี้เหลือแค่ตั้ง `SPMT07_APP_URL` และ `SPMT07_SHEET_ID` ตามตารางในหัวข้อติดตั้ง

ข้อควรรู้:

- SP-MT-07 ตั้งให้เข้าได้เฉพาะคนที่ login บัญชี Google — ในกรอบเนื้อหาจะเห็นหน้าก็ต่อเมื่อเบราว์เซอร์ login
  บัญชี Google ไว้แล้ว (หน้า login ของ Google แสดงในกรอบไม่ได้) ถ้ากรอบว่างให้กด "เปิดในแท็บใหม่"
- หน้าอนุมัติ/ลงนามจากลิงก์อีเมลของ SP-MT-07 เปิดตรงเหมือนเดิม ไม่ผ่านหน้าหลัก
- login ของหน้าหลักคุมได้แค่ว่าใครเห็นเมนูไหน คนที่มี URL ของ SP-MT-07 ยังเปิดตรงได้

## แชทบอทค้นเอกสารในคลัง

พิมพ์ชื่อบริษัท ชื่อสินค้า/บริการ ชื่องาน หรือปี พ.ศ. (หลายคำคั่นด้วยเว้นวรรค = ต้องเจอทุกคำ)
แชทบอทตอบเป็นรายการเอกสาร พร้อมสถานะ คำที่ตรงไฮไลต์ไว้ และลิงก์เปิดเอกสาร/PDF ในแท็บใหม่
ค้นเฉพาะคลังที่ระดับสิทธิ์ของผู้ใช้เปิดเมนูคลังนั้นได้ และล้างประวัติเมื่อออกจากระบบ

| คลัง | สถานะ |
|---|---|
| ระบบจัดซื้อ (SP-MT-07) | ค้นได้ — แบบคัดเลือก (แท็บ Submissions) และแบบสรุปผลการประเมินประจำปี (แท็บ Summaries) |
| WI, SP, SOP | ยังไม่ได้เชื่อม ต้องมีโค้ดระบบ WI ก่อน |

ระบบแยกโปรเจกต์กันจึงเรียกฟังก์ชันของกันไม่ได้ `Search.gs` จึงอ่านสเปรดชีตของ SP-MT-07 ตรงๆ แบบอ่านอย่างเดียว
ตามชื่อคอลัมน์ของระบบนั้น — **บัญชีที่ deploy หน้าหลักต้องเปิดสเปรดชีต SP-MT-07 ได้** (ใช้บัญชีเดียวกับที่ deploy
SP-MT-07 ง่ายที่สุด) และถ้า SP-MT-07 เปลี่ยนชื่อคอลัมน์ ต้องแก้ `Search.gs` ตาม
ทะเบียน AVL / Lab List ยังไม่รวมในการค้น

## เชื่อมระบบส่งไฟล์ WI พร้อมลายเซ็นออนไลน์

เมนู 4 รายการใต้ "WI, SP, SOP" เปิดหน้าของระบบ WI ในกรอบเนื้อหา:

| เมนู | หน้าในระบบ WI |
|---|---|
| ส่งคำขอแก้ไขเอกสาร | `?page=dar` (คำขอเอกสาร / DAR) |
| ส่งเอกสารที่แก้พร้อมลงนาม | `?page=upload` (ส่งเอกสารขอลงนาม) |
| ติดตามสถานะ | `?page=home` (หน้ารวม — เอกสารรอลงนาม ใกล้ถึงกำหนดทบทวน) |
| คลังเอกสาร | `?page=archive` |

**ขั้นที่ 1 — ใช้ระบบ WI ที่ deploy อยู่แล้ว** (ต้องแก้ฝั่ง WI 2 จุด)

1. `doGet` ของระบบ WI ต้องอนุญาตให้แสดงในกรอบ:
   `.setXFrameOptionsMode(HtmlService.XFrameOptionsMode.ALLOWALL)` — ไม่ใส่แล้วกรอบเนื้อหาจะว่าง
2. เมื่อมี `?embed=1` ให้ซ่อนแถบเมนูของ WI เอง (`Nav.html`) — ลิงก์ในแถบนั้นใช้ `target="_top"`
   กดแล้วจะพาออกจากหน้าหลัก (ทำแบบเดียวกับที่ทำใน SP-MT-07: `doGet` ส่งตัวแปร `embed` ให้ template
   แล้วหน้าเว็บได้ `<body class="embed">` ซึ่ง CSS ซ่อนลิงก์เหล่านั้น)

ข้อจำกัดของขั้นนี้: login ของหน้าหลักคุมได้แค่ว่าใครเห็นเมนูไหน คนที่มี URL ของระบบ WI ยังเปิดตรงได้ตามสิทธิ์เดิมของ WI

**ขั้นที่ 2 — รวมเป็นโปรเจกต์เดียว** (ทำได้เมื่อมีซอร์สโค้ด `wi-doc-control`)

ย้ายไฟล์ของระบบ WI เข้ามาโปรเจกต์นี้ เปลี่ยนเมนูจาก `app/page` เป็น `file` และให้ฟังก์ชันฝั่ง server
ของ WI ตรวจสิทธิ์ด้วย `requireLevel_(token, …)` — จากนั้น login เดียวคุมได้ทั้งระบบ
หน้าลงนามจากลิงก์อีเมล (`?page=sign&id=…&token=…`) ต้องเปิดได้โดยไม่ต้อง login เหมือนเดิม
จึงต้องรวม `doGet` ของสองระบบให้ส่งหน้านั้นต่อไปยังโค้ดเดิมของ WI

## ยังไม่ได้ทำ

- **แชทบอท** ยังค้นคลัง WI, SP, SOP และทะเบียน AVL / Lab List ไม่ได้
- **กันเดารหัสผ่าน** ยังไม่จำกัดจำนวนครั้งที่ login ผิด
- **ลืมรหัสผ่าน** ผู้ดูแลระบบตั้งรหัสใหม่ให้ที่หน้าจัดการผู้ใช้ ยังไม่มีระบบรีเซ็ตทางอีเมล
- session อยู่ได้ 6 ชั่วโมง (ขีดสูงสุดของ CacheService) และหายเมื่อปิดแท็บ
