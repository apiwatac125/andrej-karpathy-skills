# ระบบงานเอกสาร — กลุ่มงานพยาธิวิทยาคลินิกและเทคนิคการแพทย์ โรงพยาบาลเลิดสิน

หน้าหลักที่รวมระบบงานเอกสารทั้งหมดไว้ในที่เดียว ตามแบบร่าง:

- **แถบซ้าย** — ข้อมูลผู้ใช้ (ชื่อ ระดับสิทธิ์ งาน) พร้อมปุ่ม ‹ ซ่อนแถบ แล้วตามด้วยเมนูแยกกลุ่ม
  - WI, SP, SOP › ส่งคำขอแก้ไขเอกสาร · ส่งเอกสารที่แก้พร้อมลงนาม · ติดตามสถานะ · คลังเอกสาร · ทะเบียนเอกสาร (Master List) · ตรวจติดตามภายใน · CAPA (ระบบ WI Document Control)
  - ระบบจัดซื้อ › คัดเลือกผู้ขาย / ผู้ให้บริการ · ประเมินผู้ขาย · คลังเอกสาร · ดรอปดาวน์รายชื่อบริษัท (ระบบ SP-MT-07)
  - ช่องสำรองสำหรับระบบใหม่ 3 ช่อง
- **หัว** — โลโก้ + "ระบบงานเอกสาร กลุ่มงานพยาธิวิทยาคลินิกและเทคนิคการแพทย์ โรงพยาบาลเลิดสิน"
- **กรอบเนื้อหา** — หน้าจอของระบบที่เลือกจากเมนู
- **แชทบอท** — ปุ่มมุมขวาล่าง ค้นเอกสารในคลัง
- จอโทรศัพท์: แถบซ้ายกลายเป็นลิ้นชัก เปิดด้วยปุ่ม ☰

เขียนด้วย Google Apps Script (HtmlService + Google Sheets) — ระบบ WI รวมอยู่ในโปรเจกต์นี้แล้ว (login เดียว)
ส่วนระบบจัดซื้อ SP-MT-07 deploy แยกและฝังในกรอบ

## ติดตั้ง

1. สร้างโปรเจกต์ใหม่ที่ <https://script.google.com> แล้วคัดลอกไฟล์ `.gs` และ `.html` ทั้งหมดเข้าไป
   (ชื่อไฟล์ต้องตรงตาม `.claspignore`) และเปิด Project Settings › Show "appsscript.json" แล้ววางเนื้อหาจากไฟล์นี้
   — หรือใช้ clasp ตามหัวข้อ "Deploy ด้วย clasp" ด้านล่าง (โปรเจกต์ของกลุ่มงานสร้างไว้แล้ว)
2. เลือกฟังก์ชัน `setup` แล้วกด Run (อนุญาตสิทธิ์ครั้งแรก) — ระบบสร้างสเปรดชีต
   "ระบบงานเอกสาร — ผู้ใช้และสิทธิ์" และบัญชี `admin` ระดับผู้ดูแลระบบ
   **รหัสผ่านชั่วคราวอยู่ใน Execution log**
   - รันซ้ำได้ ถ้าบัญชี `admin` มีอยู่แล้วแต่ยังไม่มีผู้ดูแลระบบ จะปรับ `admin` เป็นผู้ดูแลระบบให้ (รหัสผ่านเดิม)
   - ถ้าอยากเก็บผู้ใช้ในสเปรดชีตที่มีอยู่แล้ว ให้ตั้ง Script Property `DB_SHEET_ID` เป็น ID ของสเปรดชีตนั้นก่อนรัน
   - `setup()` เรียก `runSetup()` ของระบบ WI ต่อ — สร้างสเปรดชีต "WI Document Control" (id เก็บที่ `SHEET_ID`)
     แล้วตั้งอีเมลผู้ทบทวน/ผู้อนุมัติในแท็บ Units / Config ของชีตนั้น ตาม `wi/README.md` หัวข้อติดตั้ง ข้อ 4
3. Deploy › New deployment › Web app — Execute as: **Me**, Who has access: **Anyone**
4. เปิด URL ที่ได้ เข้าสู่ระบบด้วย `admin` แล้ว **เปลี่ยนรหัสผ่านทันที** จากนั้นเพิ่มผู้ใช้ที่เมนู "จัดการผู้ใช้และสิทธิ์"
5. เชื่อมระบบอื่น — ผู้ดูแลระบบแก้ได้ที่หน้า "ตั้งค่าระบบ" ในเว็บ (หรือที่ Project Settings › Script Properties)

   | Property | ค่า |
   |---|---|
   | `SPMT07_APP_URL` | URL เว็บแอป SP-MT-07 production (deploymentId อยู่ใน CLAUDE.md ของ repo `spmt07-webapp`) |
   | `SPMT07_SHEET_ID` | id สเปรดชีต "SP-MT-07 Selection Submissions" (ส่วนยาวใน URL ของชีต ระหว่าง `/d/` กับ `/edit`) — ใช้กับแชทบอท |

   ค่าเหล่านี้ไม่เขียนไว้ใน repo เพราะ repo นี้เปิดสาธารณะ — URL ระบบจริงของโรงพยาบาลไม่ควรอยู่ที่สาธารณะ
   ถ้ามีไฟล์ `LocalProps.gs` (ดูหัวข้อ Deploy ด้วย clasp) `setup()` จะเติมให้เองเฉพาะตัวที่ยังว่าง

## Deploy ด้วย clasp

`.clasp.json` ในโฟลเดอร์นี้ชี้ไปที่โปรเจกต์ Apps Script "ระบบงานเอกสาร" ของกลุ่มงาน และ `.claspignore`
push ขึ้นไปเฉพาะไฟล์ของระบบ (ไม่เอา README / preview)

```bash
clasp push
clasp list-deployments          # ดู deploymentId ของตัว production
clasp deploy --deploymentId <deploymentId> --description "..."
```

`clasp push` อย่างเดียวลิงก์ production ยังใช้โค้ดเดิม ต้อง `clasp deploy --deploymentId` ทุกครั้ง

`LocalProps.gs` (อยู่ใน `.gitignore`) ใช้ส่งค่า Script Properties ขึ้นไปพร้อมโค้ดโดยไม่ต้องพิมพ์เองในหน้า Project Settings:

```js
var LOCAL_PROPS = { SPMT07_APP_URL: 'https://script.google.com/macros/s/…/exec', SPMT07_SHEET_ID: '…' };
```

push แล้วรัน `setup()` หนึ่งครั้ง ค่าจะถูกคัดลอกลง Script Properties — push ครั้งหลังที่ไม่มีไฟล์นี้ก็ไม่เป็นไร

## ระดับสิทธิ์

5 ระดับ เรียงจากสูงไปต่ำ: **ผู้ดูแลระบบ (admin)** › หัวหน้ากลุ่มงาน › หัวหน้างาน › ผู้ปฏิบัติงาน › อื่นๆ

| เมนู | ผู้ดูแลระบบ | หัวหน้ากลุ่มงาน | หัวหน้างาน | ผู้ปฏิบัติงาน | อื่นๆ |
|---|:-:|:-:|:-:|:-:|:-:|
| ส่งคำขอแก้ไขเอกสาร | ✓ | ✓ | ✓ | ✓ | – |
| ส่งเอกสารที่แก้พร้อมลงนาม | ✓ | ✓ | ✓ | ✓ | – |
| ติดตามสถานะ | ✓ | ✓ | ✓ | ✓ | – |
| คลังเอกสาร (WI) | ✓ | ✓ | ✓ | ✓ | ✓ |
| ทะเบียนเอกสาร (Master List) | ✓ | ✓ | ✓ | ✓ | ✓ |
| ตรวจติดตามภายใน | ✓ | ✓ | ✓ | – | – |
| CAPA | ✓ | ✓ | ✓ | ✓ | – |
| คัดเลือกผู้ขาย / ผู้ให้บริการ | ✓ | ✓ | ✓ | ✓ | – |
| ประเมินผู้ขาย | ✓ | ✓ | ✓ | ✓ | – |
| คลังเอกสาร (ระบบจัดซื้อ) | ✓ | ✓ | ✓ | ✓ | – |
| ดรอปดาวน์รายชื่อบริษัท | ✓ | ✓ | ✓ | – | – |
| จัดการผู้ใช้และตั้งค่าระบบ | ✓ | – | – | – | – |

- นี่คือค่าเริ่มต้น (`minLevel` ใน `Config.gs`) ผู้ดูแลระบบเปลี่ยนระดับของแต่ละเมนูได้ที่หน้า "ตั้งค่าระบบ"
  และหน้า "จัดการผู้ใช้และสิทธิ์" แสดงตารางนี้จากค่าที่ใช้จริงเสมอ
- **ผู้ดูแลระบบแก้ได้ทุกอย่างจากหน้าเว็บ**: เพิ่ม/แก้ผู้ใช้และกำหนดระดับ (รวมตั้งผู้ดูแลระบบคนอื่น) ตั้งรหัสผ่านใหม่
  ปิดบัญชี และหน้า "ตั้งค่าระบบ" (ชื่อระบบ หน่วยงาน โลโก้ · ลิงก์เชื่อมระบบ SP-MT-07 · ระดับสิทธิ์ของแต่ละเมนู)
- ถ้าให้หัวหน้ากลุ่มงานจัดการผู้ใช้และตั้งค่าได้ด้วย เปลี่ยน `ADMIN_LEVEL` ใน `Config.gs` เป็น 4
- เพิ่มระดับใหม่ได้ที่ `ROLES` ใน `Config.gs`
- ผู้ใช้เห็นเฉพาะเมนูที่ระดับของตัวเองเปิดได้ และ server ตรวจสิทธิ์ซ้ำทุกครั้งที่เปิดเมนู
- **หน้าที่ในระบบคุณภาพ** (`DUTIES` ใน `Config.gs`) ติดที่ตัวผู้ใช้ แยกจากระดับ เพราะไม่ใช่ลำดับสูงต่ำ:
  **QMR** · **Auditor** — ผู้ดูแลระบบติ๊กให้ที่หน้าจัดการผู้ใช้ และแถบซ้ายแสดงต่อท้ายระดับ (เช่น "หัวหน้างาน · QMR")
  ผู้ดูแลระบบทำได้ทุกหน้าที่ · ตอนนี้ใช้กับ "ขึ้นทะเบียนเอกสารเดิม" (เฉพาะ QMR) — อีเมล QM ที่ลงนามปิด Audit/CAPA
  ยังตั้งในชีต WI (`qm_email`) เหมือนเดิม
- เปลี่ยนระดับหรือปิดบัญชีแล้วมีผลทันที (session เก็บแค่ชื่อผู้ใช้ สิทธิ์อ่านจากชีตใหม่ทุกครั้ง)
- ผู้ดูแลระบบลดสิทธิ์หรือปิดบัญชีของตัวเองไม่ได้ กันระบบเหลือแต่ผู้ใช้ที่จัดการสิทธิ์ไม่ได้
- หน้าตั้งค่ารับเฉพาะลิงก์ที่ขึ้นต้นด้วย `https://` และตรวจทุกช่องก่อนบันทึก ช่องไหนผิดจะไม่บันทึกอะไรเลย

## เพิ่มระบบใหม่ในช่องสำรอง

แทนที่ `{ slot: true }` ใน `MENU` ด้วยกลุ่มเมนูจริง เช่น

```js
{
  group: 'ระบบความเสี่ยง',
  items: [
    { id: 'risk-report', label: 'รายงานความเสี่ยง', minLevel: 2, app: 'RISK_APP_URL', page: 'report' }
  ]
},
```

- `app` + `page` — ระบบที่ deploy แยก: ตั้ง Script Property ชื่อตาม `app` เป็น URL เว็บแอป ระบบจะโหลด `URL?page=report&embed=1`
- `wi` — หน้าของระบบ WI ในโปรเจกต์นี้ (`?page=<ค่า wi>`) ใช้กับกลุ่ม WI เท่านั้น
- `file` — หน้าที่อยู่ในโปรเจกต์นี้เอง: สร้าง `ชื่อไฟล์.html` แล้วใส่ `file: 'ชื่อไฟล์'` หน้านั้นได้ตัวแปร `user` และ `token`
  ใน template และเปิดได้เฉพาะคนที่สิทธิ์ถึง
- ไม่ใส่ทั้งสองอย่าง = แสดง "เร็วๆ นี้" และหน้า "อยู่ระหว่างพัฒนา" ใช้จองเมนูไว้ก่อนระบบพร้อม

## เชื่อมระบบจัดซื้อ (SP-MT-07 คัดเลือกและประเมินผู้ขาย)

ระบบ SP-MT-07 (repo `Unlucky125/spmt07-webapp`) deploy แยกโปรเจกต์ใช้งานจริงอยู่แล้ว เมนูใต้ "ระบบจัดซื้อ"
เปิดหน้าของระบบนั้นในกรอบเนื้อหา:

| เมนู | หน้าใน SP-MT-07 |
|---|---|
| คัดเลือกผู้ขาย / ผู้ให้บริการ | หน้าแรก (แบบคัดเลือก FR-SPMT07-01 / -09) |
| ประเมินผู้ขาย | `?page=summary` (สรุปผลการประเมินประจำปี) |
| คลังเอกสาร | `?page=archive` |
| ดรอปดาวน์รายชื่อบริษัท | `?page=formtools` |

SP-MT-07 ตั้งแต่ version 28 (deploy 2026-10-29) รองรับ `?embed=1` แล้ว: หน้าเหล่านี้แสดงในกรอบได้
และซ่อนลิงก์ไปหน้าอื่นของ SP-MT-07 (ใช้เมนูซ้ายแทน) ลิงก์ Google Form ยังอยู่ เปิดตรงไม่มี `?embed=1`
เหมือนเดิมทุกอย่าง — ฝั่งนี้เหลือแค่ตั้ง `SPMT07_APP_URL` และ `SPMT07_SHEET_ID` ตามตารางในหัวข้อติดตั้ง

ข้อควรรู้:

- SP-MT-07 ตั้งให้เข้าได้เฉพาะคนที่ login บัญชี Google — ในกรอบเนื้อหาจะเห็นหน้าก็ต่อเมื่อเบราว์เซอร์ login
  บัญชี Google ไว้แล้ว (หน้า login ของ Google แสดงในกรอบไม่ได้) ถ้ากรอบว่างให้กด "เปิดในแท็บใหม่"
- หน้าอนุมัติ/ลงนามจากลิงก์อีเมลของ SP-MT-07 เปิดตรงเหมือนเดิม ไม่ผ่านหน้าหลัก
- login ของหน้าหลักคุมได้แค่ว่าใครเห็นเมนูไหน คนที่มี URL ของ SP-MT-07 ยังเปิดตรงได้

## แชทบอทค้นเอกสารในคลัง

พิมพ์เลขที่/ชื่อเอกสาร คำในเนื้อหา ชื่อบริษัท ชื่อสินค้า/บริการ ชื่องาน หรือปี พ.ศ. (หลายคำคั่นด้วยเว้นวรรค = ต้องเจอทุกคำ)
แชทบอทตอบเป็นรายการเอกสาร พร้อมสถานะ คำที่ตรงไฮไลต์ไว้ และลิงก์เปิดเอกสาร/PDF ในแท็บใหม่
ค้นเฉพาะคลังที่ระดับสิทธิ์ของผู้ใช้เปิดเมนูคลังนั้นได้ และล้างประวัติเมื่อออกจากระบบ

| คลัง | สถานะ |
|---|---|
| ระบบจัดซื้อ (SP-MT-07) | ค้นได้ — แบบคัดเลือก (แท็บ Submissions) และแบบสรุปผลการประเมินประจำปี (แท็บ Summaries) |
| WI, SP, SOP | ค้นได้ — เรียก `searchArchive()` ของระบบ WI (`DocSearch.gs`) ตรง: เลขที่ ชื่อ และเนื้อหาไฟล์ เฉพาะฉบับที่บังคับใช้ |

## ระบบ WI Document Control (รวมอยู่ในโปรเจกต์นี้)

โค้ด WI v2.2 จากโฟลเดอร์ `wi-doc-control` ในเครื่อง `D:\claude amass` (ผู้ใช้ส่งมา 2026-10-29) อยู่ในโฟลเดอร์นี้
แก้ให้น้อยที่สุด เอกสารเดิมของ WI อยู่ใน `wi/`

| เมนู | หน้าในระบบ WI |
|---|---|
| ส่งคำขอแก้ไขเอกสาร | `?page=dar` (ใบขออนุมัติ DAR) |
| ส่งเอกสารที่แก้พร้อมลงนาม | `?page=upload` |
| ติดตามสถานะ | `?page=home` (หน้ารวม — เอกสารรอลงนาม ใกล้ถึงกำหนดทบทวน CAPA เกินกำหนด) |
| คลังเอกสาร | `?page=archive` |
| ทะเบียนเอกสาร (Master List) | `?page=masterlist` (เพิ่มในระบบนี้ — `MasterList.html`) |
| ตรวจติดตามภายใน | `?page=audit` |
| CAPA | `?page=capa` |

ทำงานอย่างไร:

- `doGet` อยู่ที่ `Shell.gs` ที่เดียว ของ WI เปลี่ยนชื่อเป็น `wiDoGet_(e, embed, session)` · ชื่อที่ชนกันถูกเปลี่ยน:
  `Code.gs`/`Styles.html` ของหน้าหลัก → `Shell.gs`/`ShellStyles.html`, `ROLES` ใน `AuditCapa.gs` → `PEOPLE_ROLES`
- เปิดจากเมนู: หน้าหลักโหลด `?page=…&embed=1&s=<session>` ในกรอบ — server ตรวจ session และระดับสิทธิ์ของเมนูนั้นก่อน
  ส่งหน้า WI ไม่ผ่านก็กลับหน้า login
- **ลิงก์จากอีเมล** ของ WI: หน้าลงนาม (`?page=sign&id&token`) และลิงก์ที่มี `id` + `token` เปิดตรงได้โดยไม่ต้อง login
  เหมือนเดิม · ลิงก์อื่น (เช่น `?page=audit&id=…`) ขึ้นหน้า login ก่อน แล้วเปิดหน้านั้นให้ต่อในกรอบ
- ในกรอบ หน้า WI ซ่อนแถบเมนูและช่องค้นของตัวเอง (`data-embed="1"`) ลิงก์ภายในส่ง `postMessage` ให้หน้าหลัก
  เปิดในกรอบเดิม (`WiNav` ใน `Nav.html`) — หน้าหลักรับเฉพาะข้อความจากกรอบของตัวเองที่เป็น URL ของระบบนี้
- หน้า WI ได้ session ของผู้ใช้ที่ login (`<body data-session>` → `WiNav.session`) ส่งให้ฟังก์ชันที่ต้องรู้ตัวผู้ใช้:
  หน้าส่งเอกสาร (`getUploadInit` / `getNextDocCode` / `submitDocument` / `registerExistingDocument`) และ Master List
- อีเมลผู้ทบทวน/ผู้อนุมัติ/QM ยังตั้งในชีตของ WI (แท็บ Units / Config) แยกจากผู้ใช้ของหน้าหลัก

ข้อจำกัด (ยังไม่ได้ทำ):

- ฟังก์ชันฝั่ง server ของ WI ส่วนใหญ่ (`google.script.run`) ยังไม่ตรวจ login ของหน้าหลัก เหมือน WI เดิมที่ใครมีลิงก์ก็เรียกได้
  — ที่ตรวจแล้วคือหน้าส่งเอกสารและทะเบียนเอกสาร (ข้างบน) · ที่เหลือ login คุมแค่ว่าใครเปิดหน้าไหนได้
- แท็บ People / `enforce_roles` ของ WI ยังแยกจากระดับสิทธิ์และหน้าที่ของหน้าหลัก
- โค้ด WI ยังไม่เคยรันบน Apps Script จริง — ทดสอบแล้วแค่ตัวแยกเส้นทาง หน้าเว็บในกรอบ และการค้น (บนบริการจำลอง)
- กฎ "ไฟล์ชุดเดียวกับ `wi-doc-control-v1.1`" ใน `wi/CLAUDE.md` ใช้ไม่ได้แล้ว — ไฟล์ที่แก้ในโฟลเดอร์นี้ (Nav, หน้า HTML)
  ต่างจาก v1.1 แล้ว

## ทะเบียนเอกสาร (เพิ่ม 2026-10-31)

ต่อยอดระบบ WI ตามตัวอย่างระบบบริหารเอกสารคุณภาพที่ผู้ใช้ส่งมา (`DocRegistry.gs`, `MasterList.html`) — ใช้แท็บ
Documents เดิม ไม่มีทะเบียนแยก

**รหัสเอกสาร 3 ส่วน** `<ชนิด>-<รหัสงาน>-<ลำดับ>` เช่น `WI-MB-08`
- ชนิด = WI / SP / ED / LB / FM / QM · รหัสงาน = คอลัมน์ `unit_code` ในแท็บ **Units** ของชีต WI
  (ระบบเติมคอลัมน์ให้เองครั้งแรกที่เปิดหน้าส่งเอกสาร — **ผู้ดูแลต้องใส่รหัสของแต่ละงานเอง** เช่น MB)
- ลำดับนับแยกตามชนิด + งาน อย่างน้อย 2 หลัก (`WI-MB-08` แล้ว SP ฉบับแรกของงานเดียวกัน = `SP-MB-01`)
  เอกสารลูกก็ใช้ 3 ส่วนแบบเดียวกัน · เลขที่เคยใช้แล้ว (รวมเอกสารที่ยกเลิก/ถูกตีกลับ) ไม่ถูกนำมาใช้ซ้ำ

**หน้าส่งเอกสาร** เลือกได้ 3 แบบ
1. **เอกสารใหม่** — เลือกประเภท + งาน ระบบแสดงเลขที่ถัดไป และออกเลขจริงตอนกดส่ง (ทำทีละคำขอด้วย lock
   สองคนส่งพร้อมกันไม่ได้เลขซ้ำ) · ใบขออนุมัติ (DAR) จัดทำเอกสารใหม่จึงไม่ต้องกรอกเลขที่แล้ว
2. **แก้ไข / ทบทวนเอกสารที่มีในระบบ** — กรอกเลขที่เดิม (เลขที่ไม่มีในระบบถูกปฏิเสธ)
3. **ขึ้นทะเบียนเอกสารเดิมบนกระดาษ** (เฉพาะ QMR / ผู้ดูแลระบบ) — สำหรับเอกสารที่ลงนามและประกาศใช้แล้ว:
   ใส่เลขที่ตามที่พิมพ์บนเอกสาร ฉบับที่ วันที่ประกาศใช้ แนบไฟล์สแกน → เป็นเอกสาร "อนุมัติแล้ว" ทันที
   ไม่ส่งอีเมล ไม่มีใบปก (ลายมือชื่ออยู่บนต้นฉบับกระดาษ) บันทึกชื่อผู้ขึ้นทะเบียน + เวลาไว้
   (`registered_by` / `registered_at`) · หน้าคลังแสดง "ลงนามบนกระดาษ" · แก้ไข/ทบทวนครั้งต่อไปผ่านการลงนามในระบบตามปกติ
- ชื่อ-อีเมลผู้จัดทำเติมจากบัญชีที่ login

**Master List** (`?page=masterlist`) 1 แถวต่อ 1 รหัส แสดงฉบับปัจจุบัน — คอลัมน์ตามทะเบียนกระดาษ (ลำดับ รหัส ชื่อ
ประเภท ฉบับที่ แก้ไขครั้งที่ วันที่ประกาศใช้ ครบกำหนดทบทวน งาน สถานะ) กรองตามประเภท / งาน / สถานะ / คำค้น
แล้วพิมพ์หรือบันทึก PDF ขนาด A4 · ใช้งาน = มีฉบับอนุมัติแล้ว · ยกเลิก = ทุกฉบับยกเลิกใช้ ·
รหัสที่ยังไม่เคยอนุมัติไม่ขึ้นทะเบียน · อ่านเฉพาะคอลัมน์ที่ใช้ (ไม่ดึงคอลัมน์ลายเซ็น)

**แผนต่อจากนี้** (ตามลำดับที่เสนอผู้ใช้): ทะเบียนสำเนา + บันทึกยกเลิก/ทำลาย (เรียกคืนสำเนา พยาน) →
ยืนยันการอ่าน (เลือกผู้อ่านรายคน) + เมนู "เอกสารที่ต้องอ่าน" → หน้าเอกสารครบกำหนดทบทวน + อีเมลเตือน + Dashboard
+ หน้ารายงาน + ประวัติการใช้งาน → AI สรุปเอกสาร (ต้องตกลงเรื่องค่าใช้จ่าย และ WI เดิมเลือกไม่ใช้ LLM) · LINE ข้ามไปก่อน

## ยังไม่ได้ทำ

- **แชทบอท** ยังค้นทะเบียน AVL / Lab List ไม่ได้
- **ระบบ WI** ยังไม่ตรวจ login ในฟังก์ชันฝั่ง server (ดูหัวข้อระบบ WI)
- **กันเดารหัสผ่าน** ยังไม่จำกัดจำนวนครั้งที่ login ผิด
- **ลืมรหัสผ่าน** ผู้ดูแลระบบตั้งรหัสใหม่ให้ที่หน้าจัดการผู้ใช้ ยังไม่มีระบบรีเซ็ตทางอีเมล
- session อยู่ได้ 6 ชั่วโมง (ขีดสูงสุดของ CacheService) และหายเมื่อปิดแท็บ
