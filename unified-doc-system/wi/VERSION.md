## v2.1 เพิ่มอะไรจาก v2.0

**โมดูล DAR — Document Approval Request (ใบขออนุมัติดำเนินการกับเอกสาร)**

เติมขั้นที่หายไปหน้าโมดูลเอกสาร เดิมระบบเริ่มที่ "อัปโหลดไฟล์ที่ร่างเสร็จแล้ว"
แปลว่าผู้จัดทำลงแรงร่างก่อน แล้วค่อยรู้ตอนทบทวนว่าไม่ควรแก้ตั้งแต่แรก

```
v2.0  ✗ ไม่มี          → ร่าง+อัปโหลด → ทบทวน → อนุมัติ → บังคับใช้
v2.1  DAR (ขออนุญาต)  → ร่าง+อัปโหลด → ทบทวน → อนุมัติ → บังคับใช้
      + ประเมินผลกระทบ
```

**3 ประเภทคำขอ**
| ประเภท | เกิดอะไรขึ้นเมื่ออนุมัติ |
|---|---|
| จัดทำเอกสารใหม่ | ผู้ขอได้ลิงก์ไปหน้าอัปโหลดที่เติมข้อมูลจากคำขอให้แล้ว |
| แก้ไขเอกสาร | เหมือนข้างบน + ล็อกเลขที่เอกสารตามคำขอ |
| **ยกเลิกเอกสาร** | ตีเอกสารเป็น "ยกเลิกใช้" ทันที — **ปิดช่องว่างของ v1.0/v2.0 ที่ยกเลิกเอกสารได้ทางเดียวคือมีฉบับใหม่มาแทน** |

**การประเมินผลกระทบ** (ส่วนที่ทำให้ใบขออนุมัติมีค่าจริง) — 3 ข้อในฟอร์ม:
ต้องอบรมผู้ปฏิบัติใหม่ไหม · **กระทบผลตรวจที่รายงานออกไปแล้วไหม** (ถ้าใช่ หน้าจะเตือนเรื่อง ISO 15189 ข้อ 7.5) ·
เอกสารอื่นที่ต้องแก้ตาม

**เส้นที่ปิดครบแล้ว**
```
v2.0:  CAPA ··········· WI Rev ใหม่      (ผูกย้อนหลังด้วยมือ คนลืมได้)
v2.1:  CAPA → DAR → WI Rev ใหม่          (เส้นเกิดเองตั้งแต่ต้น)
```
หน้า CAPA มีปุ่ม "เปิดใบขออนุมัติแก้เอกสาร (DAR) จาก CAPA นี้" ที่ดึงปัญหา/สาเหตุราก/แนวทางแก้ไข
มาเป็นเหตุผลของคำขอให้เลย — เอกสารที่ออกตามคำขอจะผูกกลับมาที่ DAR อัตโนมัติตอนอนุมัติครบ

**บังคับหรือไม่บังคับก็ได้** — Config `require_dar` (ค่าตั้งต้น `FALSE`)
FALSE = ส่งเอกสารตรงได้ตามเดิม ใช้ DAR เฉพาะกรณีที่อยากคุม · TRUE = ไม่มี DAR ที่อนุมัติแล้ว ส่งเอกสารไม่ได้
ตั้งไว้ให้ทยอยปรับตัวได้ ไม่ต้องเปลี่ยนพฤติกรรมทั้งแล็บในวันเดียว

**refactor ที่ตามมา** — ย้าย helper ที่ใช้ร่วมกัน (`readTable_`, `findRowById_`, `appendByName_`,
`nextSerial_`, `toIsoDate_`, `isOverdue_`, `sigHtml_`, `pdfCss_` ฯลฯ) จาก `AuditCapa.gs` ไป **`Common.gs`**
เพื่อให้ `DocRequest.gs` ใช้ได้โดยไม่ต้องลาก Audit/CAPA ไปด้วย — v1.1 จึงใช้ไฟล์ DAR ชุดเดียวกันได้

**ไฟล์ใหม่:** `Common.gs`, `DocRequest.gs`, `Dar.html`
**แท็บใหม่:** `DocRequests` · **คอลัมน์ใหม่ใน Documents:** `dar_id`
**Config key ใหม่:** `require_dar`, `dar_approver_title`

**อัปเกรดจาก v2.0 ที่ deploy แล้ว** — คัดลอกไฟล์ใหม่ทับ แล้วรัน `runSetup()` อีกครั้ง
(idempotent — เติมแท็บ/คอลัมน์/คีย์ที่ขาดให้เอง ไม่ลบข้อมูลเดิม) แล้ว Deploy **New version**
ของเดิมทำงานต่อได้ทันทีเพราะ `require_dar = FALSE`

## แก้ให้ตรงเอกสารจริง (จากตัวอย่าง WI-MB-08 / WI-MB-07)

หลังได้ไฟล์ WI ที่ใช้งานจริงมาเทียบ ปรับ data model ตามนี้:

| ของจริง | ที่แก้ |
|---|---|
| ฉบับที่เป็น `D/1` เดิน `1 → 2 → C → D → D/1` | เลิกใช้ `revision` เป็นเลขที่แสดง — เพิ่ม `edition` (string) + `amendment` (int) + `edition_label` · `revision` เหลือเป็นลำดับภายในสำหรับเรียงเท่านั้น |
| 3 ตัวนับแยก: ฉบับที่ / ทบทวนครั้งที่ / แก้ไขครั้งที่ | เพิ่ม `review_count` + `change_kind` (`new`/`edition`/`amend`/`review`) · รองรับแถว "ทบทวนเอกสาร (ไม่มีแก้ไข)" ที่ฉบับที่ไม่เปลี่ยน |
| ประเภทจริง WI / SP / ED / LB | `DOC_TYPES` เปลี่ยนทั้งชุด (เดิมเป็น WI/SOP/FM/QM) |
| ตารางประวัติมีคอลัมน์ "หน้าที่" | เพิ่ม `change_pages` |
| เอกสารควบคุม / ไม่ควบคุม + สำเนาฉบับที่ | เพิ่ม `control_type` + `copy_no` และพิมพ์ลงใบปก |
| วันที่ประกาศใช้ · ขอบข่าย · ฉบับที่ | เปลี่ยนคำศัพท์ทั้งระบบ (เดิมใช้ วันที่มีผลบังคับใช้ / Revision) |

ฉบับที่เป็นตัวอักษรได้ ระบบจึง**ไม่บวกเลขอัตโนมัติ** — `nextEdition_()` แค่เดาค่าตั้งต้น
(ตัวเลข +1, ตัวอักษรเลื่อนตัวถัดไป) แล้วให้คนกรอกแก้ทับ เพราะของจริงเคยกระโดดจาก `2` ไป `C`
ตอนเปลี่ยนระบบเลขเอกสาร · server กันฉบับซ้ำให้แทน

**ยืนยันว่าตรงอยู่แล้ว:** ลงนาม 3 ขั้น จัดทำ → ทบทวน → อนุมัติ ตรงกับหัวเอกสารจริงเป๊ะ
(นักเทคนิคการแพทย์ → หัวหน้างานจุลชีววิทยาคลินิก → หัวหน้ากลุ่มงานพยาธิวิทยาคลินิกและเทคนิคการแพทย์)

**ยังไม่ได้ทำ (ระดับ C):** parent-child ของรหัสลูก (`ED-WIMB08-01` = ED ของ WI-MB-08),
template generator โครง WI 8 หัวข้อ, บันทึกระยะเก็บหลังยกเลิก 1 ปีตอนอนุมัติ DAR ประเภทยกเลิก

## ค้นหาเนื้อหาในคลัง (ไม่ใช้ LLM)

`DocSearch.gs` + แท็บ `DocText` — ดึงข้อความจากไฟล์**ครั้งเดียวตอนอนุมัติ** เก็บไว้ แล้วค้นจากตรงนั้น
ไม่มีข้อมูลออกนอกบัญชี Google ขององค์กร และ**ไม่มีทางตอบมั่ว** เพราะคืนข้อความจริงจากเอกสาร ไม่ได้เรียบเรียงใหม่

- แปลงไฟล์ด้วย `Drive.Files.create` (Advanced Drive Service v3, ประกาศใน `appsscript.json` แล้ว)
  → Google Doc ชั่วคราว → `getBody().getText()` → ลบไฟล์ชั่วคราวทิ้ง · PDF สแกนถูก OCR ให้เอง (`ocrLanguage: 'th'`)
- เก็บเป็น chunk ละ 45,000 ตัวอักษร เพราะเซลล์ Sheets รับได้ 50,000
- `searchArchive(query, opts)` — ทุกคำต้องเจอ (AND) ทั้งใน metadata และเนื้อหา คืน snippet ±110 ตัวอักษร
  **ค่าตั้งต้นค้นเฉพาะฉบับ "อนุมัติแล้ว"** เพราะถ้าโผล่ฉบับยกเลิกใช้ คนจะหยิบวิธีปฏิบัติเก่าไปใช้ (ผิดข้อ 8.3)
- `reindexArchive(limit)` — ทำ index ย้อนหลังให้ของเดิม เรียกจาก Apps Script editor ทีละ ~10 ฉบับ
  (GAS จำกัดการรัน 6 นาที)
- **UI อยู่ที่ widget ลอยมุมขวาล่าง** (อยู่ใน `Nav.html` จึงติดไปทุกหน้า ไม่ใช่เฉพาะหน้าคลัง)
  กดเปิด/ปิด · Esc ปิด · พิมพ์แล้วค้นอัตโนมัติ (debounce 350 ms) · บนจอเล็กกางเต็มความกว้าง
  แถบบนบอก "ค้นถึงเนื้อหาในไฟล์ได้ X จาก Y ฉบับ" ให้รู้ว่า index ครบหรือยัง
- หน้าคลังเหลือแค่โหมดเรียกดู (งาน → หมวด → รายการ) ช่องค้นหาเดิมที่หัวหน้าถูกถอดออก

**ต้องทำตอนติดตั้ง:** Apps Script → Services → เพิ่ม **Drive API v3** (หรือ push `appsscript.json` ที่มีให้แล้ว)
แล้ว re-authorize เพราะเป็น scope ใหม่
